STORY

작업하면서 해결한 문제

운영 중인 쇼핑몰이라 기존 구조는 지키고, 클라이언트 피드백이 올 때마다 수정본을 다시 만들어 전달했습니다.

PROBLEM 01

카페24 기본 CSS가 디자인을 덮어씀

로그인 버튼에 둥근 모서리가 계속 남았습니다. 기본 모듈 CSS가 ID 선택자와 !important로 걸려 있었기 때문입니다.

해결 로그인, 회원가입, 아이디·비밀번호 찾기를 각각 전용 래퍼로 감싸 같은 우선순위로 덮어쓰고, 인풋과 버튼의 가로 폭과 정렬을 하나의 규칙으로 통일했습니다.

Cafe24 module CSS · specificity · scoped wrapper

PROBLEM 02

갤러리 사진이 한꺼번에 떠서 오류처럼 보임

Style 페이지는 작품 사진을 카테고리별로 보여줍니다. 필터나 More를 누르면 사진이 따닥거리며 뜨고, 필터가 사진을 전부 숨겨 버리는 충돌도 있었습니다.

해결 공용 필터 핸들러와 속성명이 겹쳐서 갤러리 전용 속성으로 분리했습니다. 사진은 순서대로 부드럽게 나타나게 하고, More는 12장씩 불러오게 했습니다.

jQuery · data attribute · staggered fade-in · lightbox

PROBLEM 03

서버 없이 문의를 메일로 받기

카페24에는 직접 만든 폼을 받아 줄 서버가 없습니다. 외부 폼 서비스를 연결했더니 수신 메일에서 한글 항목명이 깨졌습니다.

해결 항목명은 영문으로 보내고, 한글 라벨은 본문 안에 직접 넣어 메일에서 읽을 수 있게 했습니다. 필수 입력과 개인정보 동의 검증도 함께 넣었습니다.

Web3Forms · FormData · validation

SEO

검색 노출을 위한 작업

새 도메인 연결부터 검색엔진 등록, 메타 태그와 구조화 데이터 적용까지 직접 진행했습니다.

  • 도메인 연결

    기존 주소에서 새 도메인(13monthsflower.shop)으로 연결하고 DNS 설정을 점검했습니다.

  • 검색엔진 등록

    네이버 서치어드바이저, 구글 서치 콘솔에 사이트를 등록하고 카페24 SEO 설정에 사이트 소유 확인 메타 태그를 넣었습니다.

  • Title · Description · Canonical · Open Graph

    페이지별로 제목과 설명 문구를 따로 작성하고, 대표 URL(canonical)과 SNS 공유 미리보기(Open Graph)를 설정했습니다.

  • 구조화 데이터(JSON-LD)

    매장 정보를 schema.org 형식의 JSON-LD로 넣어 검색엔진이 읽을 수 있게 했습니다.

  • 이미지 대체 텍스트와 지연 로딩

    갤러리 이미지에 alt 텍스트를 넣고, loading="lazy"로 첫 화면 로딩 부담을 줄였습니다.

  • 사이트맵 점검

    카페24가 자동 생성하는 sitemap.xml에는 직접 만든 페이지(/13months/…)가 포함되지 않는 구조를 확인했습니다.

PROPOSAL

제안서로 정리한 작업 범위와 다음 단계

작업 당시 쓴 기획 문서(클래스 랜딩 기획안, SEO 문구 세트)를 클라이언트 제안서 형식 11장으로 재구성했습니다. 01–09장은 제안, 10–11장은 1단계 결과 보고입니다.

  • 진단 → 제안 → 수행

    “찾아오는 길과 예약까지 가는 길이 막혀 있다”는 진단 하나로 시작해, 제안 세 가지와 실제 결과까지 한 문서로 이었습니다.

  • 제안 C는 실제로 적용

    07장 검색 노출 제안 중 6건을 운영 사이트에 적용했고, 10장에 결과로 정리했습니다.

  • 06장 랜딩은 제안 단계

    클래스 랜딩은 구성안과 와이어프레임까지 제안한 상태이며, 아직 만들지 않았습니다.
